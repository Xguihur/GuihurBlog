# 博客与文档编写规范（内部）

> 用途：仅供自己写作时查阅，不对外展示。  
> 适用范围：本仓库 `GuihurBlog`，自 `2026-05-07` 起执行。

## 1. 总体原则

1. 先分内容类型，再分主题：  
   `docs` 放可复用知识；`blogs` 放时间性记录、经历、感受；`news` 放独立归档的每日晨报。
2. 分类（`categories`）保持少而稳；标签（`tags`）负责细分。
3. 每篇文章只设 **1 个主分类**，避免分类页混乱。

## 2. 内容分轨规则

### 2.1 docs（知识库）

适合内容：
1. 技术原理、方案总结、排查手册、最佳实践。
2. 可长期复用、可反复检索的内容。
3. 运动中偏“知识型”的内容（例如训练理论、动作笔记）也可进入 docs。

不建议内容：
1. 一次性心情记录、旅行日记、阶段感悟（这些放 blogs）。

### 2.2 blogs（时间流）

适合内容：
1. 生活经历、阶段反思、运动打卡、比赛记录、旅行记录。
2. 与时间强相关、强调叙事和感受的内容。

### 2.3 news（每日晨报）

晨报独立放在 `news/`，不放入 `blogs/`，不进入博客列表、时间线与分类。收录热点、AI 工作流、科技股、电车、骑行、飞盘和徒步路线，保留原始来源链接。

## 3. 分类与标签规范

## 3.1 blogs 的分类（固定枚举）

`blogs` 只允许以下 `categories`：
1. `life`：生活经历、旅行、日常记录。
2. `thoughts`：思考、复盘、方法论、阶段感悟。
3. `sports`：跑步/力量/球类训练与比赛记录。
4. `meta`：博客站点本身的里程碑、改版、运维变更。

## 3.2 blogs 的标签（自由词）

`tags` 用于细粒度描述，示例：
1. `旅游` `面试` `散心`
2. `跑步` `羽毛球` `力量训练`
3. `复盘` `效率` `习惯`

规则：
1. 每篇建议 1-4 个标签。
2. 优先使用已有标签写法，避免同义词分裂（例如“跑步”与“慢跑”混用）。

## 3.3 docs 的元信息

1. `docs` 不强制使用 `categories`（避免和博客分类体系混在一起）。
2. 可按需加 `tags`，用于补充检索。
3. `docs` 的主要分组依赖目录结构 + `series` 配置。

## 4. 目录结构规范

目标结构（逐步迁移，不要求一次改完）：

```text
blogs/
  life/2026/
  thoughts/2026/
  sports/2026/
  meta/2026/

docs/
  tech/
    overview.md
    frontend/
    backend/
    devops/
  sports/
    theory/
    training/

news/
  README.md
  2026/
    README.md
    11/
      README.md
      25.md
```

落地规则：
1. `blogs/<category>/<year>/<mmddNN>.md`（按时间归档，便于回溯）。
2. `docs/<domain>/<group>/<topic>.md`（按主题归档，便于检索）。
3. 文件名可先保持中文；如后续迁移英文命名，统一一次性处理。
4. `news/YYYY/MM/DD.md`：年为四位数，月、日为两位数，按晨报所标北京时间日期归档；每日 URL 为 `/news/YYYY/MM/DD.html`，不随更新改变。

## 5. Frontmatter 模板

### 5.1 blogs 模板

```yaml
---
title: 文章标题
date: 2026/05/07
categories:
 - life # life | thoughts | sports | meta
tags:
 - 标签1
 - 标签2
---
```

### 5.2 docs 模板

```yaml
---
title: 文档标题
date: 2026/05/07
tags:
 - 可选标签
---
```

### 5.3 news 模板与导入

```yaml
---
title: 资讯晨报｜2026-11-25
date: 2026-11-25
tags:
  - 每日资讯
hike_stage: 1
hike_routes:
  - 路线名称
---
```

导入时核对文件名、frontmatter 日期、正文日期一致，不按执行日期猜测；保留正文、表格、来源链接以及原有 `tags`、`hike_stage`、`hike_routes`。源文档不修改，博客副本应可独立构建，不能引用本机绝对路径、`obsidian://`、双链或嵌入。

每日正文后补充 `[本月归档](/news/YYYY/MM/)` 与 `[全部晨报](/news/)`，将占位日期替换为实际年月。已有同日内容先核对源文档，再更新原路径，不另建重复页面。

### 5.4 晨报手工维护步骤

1. 按日期检查是否已有 `news/YYYY/MM/DD.md`，导入或更新同一路径。
2. 在月度 `README.md` 中维护唯一的日报链接，按日期倒序排列。
3. 跨月、跨年时新增对应 `README.md`，在年度列月份、总览列年份，全部按日期倒序，只列已有内容的归档。
4. 总览的“最新一期”指向最新日期；没有日报时写“暂无晨报”，移除最新一期入口。
5. 更新 `.vuepress/config/series/news.ts`：总览、年度及按年月分组的月度和日报链接，最新日期优先；`/news/` 前缀已在 `series/index.ts` 注册。
6. 归档正文保留逐级入口，确保手机侧栏收起时也可浏览；每日页保留返回月度和总览的链接。
7. 构建并检查归档链路、表格与外链，确认晨报未进入博客列表、时间线与分类。

当前采用显式维护，不新增后台采集、定时同步或自动发布任务。未来同步继续复用这些稳定路径，同日写回并去重。

## 6. 展示层约束

1. “知识库”导航只指向文档入口页（如 `overview`）。
2. “博客”展示按时间流 + 分类页 + 标签页；“每日晨报”链接 `/news/`，使用独立归档和侧栏。
3. 不在 `blogs` 中使用 `undergraduate`、`w3y` 这类身份/阶段型分类名。

## 7. 存量文章迁移策略

采用“增量迁移”，不阻塞写作：
1. 新文章立即使用新规则。
2. 旧文章分批改：
   1. `undergraduate` / `w3y` / `other` 逐步映射到 `life` / `thoughts` / `sports` / `meta`。
   2. 修正标签同义词。
3. 每次迁移只处理一小批，避免大规模改动影响发布。

## 8. 发布前检查清单

1. 是否放对分轨：`docs`、`blogs` 还是 `news`。
2. `blogs` 是否使用了固定分类枚举之一。
3. `tags` 是否复用已有写法，是否过多。
4. `title`、`date` 是否完整。
5. 导航或 `series` 是否需要同步更新。
6. 晨报日期是否一致、同日是否唯一，月度、年度、总览及侧栏是否同步更新，公开内容是否无本地路径和编辑器链接。

## 9. 模板位置（内部）

写作模板存放在：
`/.vuepress/private/templates/`

包含：
1. `blog-life.md`
2. `blog-thoughts.md`
3. `blog-sports.md`
4. `blog-meta.md`
5. `doc-tech.md`
6. `doc-sports.md`

使用方式：
1. 复制对应模板到目标目录。
2. 修改 `title`、`date`、`tags`。
3. 博客文章保留模板中的固定 `categories` 值。

脚手架命令（推荐）：
1. `npm run scaffold -- blog <life|thoughts|sports|meta> "<title>"`
2. `npm run scaffold -- doc <tech|sports> <group> "<title>"`

2. 当分类规则变化时，优先更新本文档，再执行批量迁移。
